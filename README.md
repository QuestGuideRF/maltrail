# Maltrail

Maltrail — система обнаружения вредоносного сетевого трафика, состоящая из сенсора, серверной части и веб-интерфейса. Сенсор анализирует трафик через `pcapy`, сверяет его с базой trails и эвристиками, а сервер принимает события, хранит логи и отдаёт интерфейс отчётности.

## ✨ Особенности

- Сенсор для анализа трафика в реальном времени.
- Сервер для хранения событий и веб-доступа к отчётам.
- Поддержка локального режима и распределённой схемы `Sensor -> UDP -> Server`.
- Автоматические обновления trails из `trails/feeds/` и статических правил.
- Эвристики для подозрительных доменов, HTTP-запросов, прямых загрузок и сетевого поведения.
- Веб-клиент на встроенных HTML/CSS/JS ресурсах.
- Поддержка whitelist, custom trails, syslog/logstash и плагинов.

## 🚀 Быстрый старт

### Требования

- Python
- `pcapy-ng`
- root/administrator права для сенсора в типичном режиме захвата

### Установка зависимостей

```bash
pip install -r requirements.txt
```

Если `pcapy-ng` не поставился через requirements, установите его отдельно:

```bash
pip install pcapy-ng
```

### Запуск сенсора

```bash
python sensor.py
```

### Запуск сервера

```bash
python server.py
```

По умолчанию веб-интерфейс сервера доступен по адресу:

```text
http://127.0.0.1:8338
```

Файл конфигурации по умолчанию:

```text
maltrail.conf
```

Для явного указания файла конфигурации:

```bash
python sensor.py -c /path/to/maltrail.conf
python server.py -c /path/to/maltrail.conf
```

## 📁 Структура проекта

- `sensor.py` — захват и анализ трафика.
- `server.py` — HTTP/UDP сервер, логирование и запуск веб-интерфейса.
- `maltrail.conf` — основная конфигурация.
- `core/` — общая логика, HTTPD, парсинг конфигурации, логирование и обновления.
- `trails/feeds/` — динамические источники trails.
- `trails/static/` — статические сигнатуры и списки.
- `plugins/` — подключаемые обработчики событий.
- `html/` — клиентская часть интерфейса отчётов.
- `misc/` — дополнительные списки и служебные ресурсы.

## 🛠 Использование

Типовой рабочий поток:

1. Настроить `maltrail.conf`.
2. Запустить `sensor.py` на узле, где есть доступ к сетевому трафику.
3. При необходимости отдельно поднять `server.py`.
4. Открыть веб-интерфейс и анализировать журналы событий.

Что важно знать по коду:

- `server.py` принимает `-c` и `--debug`.
- `sensor.py` загружает trails, может работать с эвристиками и кэшами, и пишет события через `core.log`.
- Сервер может поднимать HTTP-панель и UDP-приёмник логов одновременно.
- Обновления trails выполняются периодически по `UPDATE_PERIOD` из конфигурации.
